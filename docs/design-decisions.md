# Design decisions: what I tested and why

Each entry is something that was measured or that broke once. Numbers are from single runs on one RTX 5060 Ti (16 GB).

## Models and speed
- **gemma4:12b writes, bge-m3 embeds.** Models are not included and have their own licences. Against the model it replaced, gemma4:12b had better accuracy, fewer repeats and lower peak VRAM, but it is 2-3x slower and its sentences run long (14.8-14.9 words).
- **Mistral Small 3.2 24B was tested as the writer and rejected.** It repeats phrases less (0.3% against 0.7% outside the setting words) but takes about 14 minutes per script against 3-7 (15 GB, partly in RAM on a 16 GB card), writes short sentences (11.4 words), and let a detail return 6-8 times in two of three scripts.
- **Cross-encoder reranker: tested and removed.** A MiniLM reranker gave no ranking gain and was 5x slower on CPU.
- **Parallel polish: 2 workers, not 3.** Three workers reached 14.8 GB VRAM, over the 14.5 GB budget (polish 18.7 s to 12.0 s with two).
- **The outline runs without thinking (`llm.think_outline: false`).** With thinking on, one run spent 185 s and the whole token budget with no JSON. Turn it on in `config.yaml` for one thinking attempt before the plain ones.

## Length and style
- **Length control.** The model wrote 3-5x small budgets, so generation is capped at about 1.8 tokens per word of budget and polish may grow a section by at most 30% (a replay showed polish pads short drafts by 16-27%, which a 15% ceiling rejected). The final fit accepts a rewrite only if it moves toward the target and adds no repeats, and runs when the script is more than 5% off (a 10% tolerance once let 823 words pass for a 750 target).
- **Per-beat polish, not whole-script.** The whole-script call made the model repeat paragraphs.
- **Sentence length needs an example, not another rule.** Five prompts already asked for short-to-medium sentences and the model wrote 7.9 words; a before/after example plus a self-check moved it to 12-16. The target is 12-16 words (`style.sentence_words`) because polish stretches sentences.
- **The rolling summary is labelled "already told".** Labelled "Summary" the model retold it; relabelling cut repeated phrases from 8.8% to 2.2% in one run.
- **One sentence splitter** (`text.sentences()`): two checks once split "J. Habakuk" differently, and a mid-sentence `[S1]` tag cut a claim in half before Verify.
- **Invented bracket notes are stripped.** Only `[PAUSE]`, `[SFX:]`, `[B-ROLL:]` and `[S#]` survive.

## Repetition
- **Repeats are guarded by tests, not hope.** A fake-model test re-tells earlier scenes and fails if any repeat reaches the script; a second test breaks the dedupe on purpose to prove the guard can fail.
- **Reworded retellings are caught by content words, not phrases.** `dedupe` drops a paragraph when at least half of its content words occur in one earlier paragraph (`checks.dedupe_similar` = 0.5; real retellings scored 0.55 and 0.75, ordinary pairs 0.37 or lower). On saved scripts it cut repeat rates from 6.7% to 4.0% and 4.9% to 0.8%.
- **The repeat guard runs before the length fit.** Run after the fit, it deleted a retold section and one run ended at 584 of 750 words. Now the fit makes up an emptied section. A test fails on the old order (660 words).
- **Recurring details are allowed, but limited.** A repeated sound or smell makes a place real, so each outline detail may come back at most 3 times (`checks.motif_max`), in different beats, changed each time. A prompt example shows a copied return and a changed one. The report lists details that return in the same words.

## Story logic and endings
- **Outline logic fields.** Without them the narrator was in two places at once. `place` is where his body is, `sees` names the screen he watches (he stays at it), `change` is the one new event, `detail` the recurring detail used. Code flags a beat with no place or change, two beats adding the same thing, and a detail used twice in a row or in more than 3 beats, then asks for one repair, kept only if it has fewer holes. A beat that shows a screen but has no `sees` takes it from the nearest beat that has one. A critic call reads the finished script for logic holes, and a second critic call checks the rewrite.
- **The ending is planned in the outline.** A horror run ended in an empty room, then found boots the story never set up, then used keys the narrator had dropped. Checking afterwards did not fix that, so the outline names the ending first: one early beat has a `plant` (an object, sound or fact shown in passing) and the outro has a `payoff` that must be that planted thing. Code flags an outline with no payoff, nothing planted, a different planted thing, or a plant after the fourth beat. `logic.dropped_then_used` adds a logic issue when a dropped object is used again, and a detail past its limit becomes an issue for the sections after it. These are word matches: they miss paraphrases and can flag an object another character took.
- **The last section is written three ways.** `Refiner.best_ending` writes `checks.ending_candidates - 1` other versions (`prompts/stages/ending.md`); a challenger replaces the current text only if the pairwise judge prefers it in both orders. It costs about a minute per script; set it to 1 to turn it off. On three 5-minute briefs against the earlier pipeline the judge scored 6 criteria each with 6 ties (horror clearly better, fantasy clearly worse, sci-fi tied) while the code metrics improved (accuracy 99.3%, no detail over its limit, was 1 of 3). Three briefs and one sample each is too few to call it a win.
- **The fantasy regression was an outline problem.** The script that lost 0-6 had recurring details labelled "Detail 1/2/3", so the detail checks matched nothing and "salt-crusted grip of my staff" came back five times, and its `change` fields were feelings ("growing desperation"), so the clerk lunged toward the light in four scenes. Six outline samples per prompt showed "Detail N" names in 6 beats with the new prompt and 0 with the old. The outline step now renames them from the narrator's list, flags a detail called "Detail N" or a `change` that is only a mood, and the prompt asks for a concrete, filmable event (afterwards: 0 generic names, 1 mood-only change in 42 beats). An earlier version also leaked snake_case names into the story; field values now become plain words.

- **Two outline repairs, and a premise check that was tried and removed.** A static `change` ("the stranger remains still") now counts as a mood, so the middle stops retelling one scene, and the outline repair may run twice. A check that every noun of the brief appears in the outline caught one real drift (a ferry story that lost its tickets) but flagged rewordings ("shape" for "figure", "researcher") in most other runs, so it was removed. Two 10-brief runs (5 min each) differed by less than the run-to-run swing (repeats 0.5-6.4%), so no later change here is claimed as a measured gain.
- **A rewrite is dropped only if it adds logic holes.** The second critic call is a small model with random output; requiring it to find zero holes rejected 13 of 24 rewrites across two runs, so a rewrite now stays unless the critic finds more holes than before.

## Evaluation
- **An absolute 1-5 score per script was tried and dropped.** A strict-editor prompt scored Premise, Hook, Voice, Prose, Logic and Ending. The 12B model gave three different scripts identical scores, missed a dropped-keys contradiction and ranked the weakest ending highest; a bigger judge (Mistral Small 3.2 24B) did the same, so the flat scoring came from asking for one grade per script, not from the model size.
- **Two scripts are compared, not graded.** `cli.py compare A B` (`prompts/stages/compare.md`) asks which script is better on each criterion and runs every pair twice with the order swapped. A criterion the two orders disagree on is a tie, and the number of such disagreements is printed as a position-bias measure. It picked a winner on most criteria where the absolute score had given 18/30 to everything. gemma judging its own writing can still favour itself, so keep one judge model for every comparison.
